# 游戏立项卡 · Game Kickoff Card

把一个模糊的游戏想法，整理成可以动手制作、可以交给 AI 的清晰方向。

> 方法论来源：游戏策划「机明」的《AI做游戏焚诀之｜游戏立项卡》。核心主张：别上来就对 AI 说"帮我做个什么游戏"——那样只会停在能跑的 Demo。先填一张立项卡，把方向定下来，再一步步做出来。策划案之于研发，正如提示词/文档之于 AI Agent。

## 什么时候用这个 skill

当用户出现以下任一情况时触发：

- 想做一款游戏（尤其是用 AI 做），但只有一个模糊想法
- 说"帮我做个 XX 游戏"却没有说清玩法、范围
- 明确要求"填立项卡 / 立项卡 / game design kickoff / scope my game idea"
- 有一个一直放在脑子里的玩法，想开始但不知从何下手

## 核心原则（必须贯穿始终）

1. **先定方向，再做实现。** 立项卡不是完整策划案，是启动前的"方向锚点"。目标是让别人（和 AI）先看懂这游戏大概怎么玩。
2. **喜欢什么可以先放开想，但要往下追一层。** 用户说"我喜欢刷装备"，要追问：到底喜欢什么？是打完 Boss 期待爆好东西，还是拿到新装备尝试新玩法？不同答案 → 完全不同的系统。
3. **填卡本身就是梳理想法的过程。** 原本零散的灵感，会在填写中逐渐清楚。你的提问就是帮用户"树立脑海中那个游戏"。
4. **带着约束做取舍。** 没有美术团队？那就找免费素材、选像素风、用回合制控制制作量。喜欢可以放开想，但真正动手时要看自己能做到什么程度。
5. **你是协作者，不是代填者。** 关键创意决定由用户拍板。你负责提问、追问、找出没说清的地方，并给出选项，但由用户决定哪些留下、哪些暂时不做。

## 交互流程

一次只专注一到两项，用自然对话逐项推进。不要一次把 5 个问题全抛给用户。每一项拿到回答后，做一次"追问是否说清"，再进入下一项。

### 第 1 项 · 一句话说清这是什么游戏
问：**"玩家扮演谁？主要做什么？"**
- 要求用一两句话说清楚。世界观可以后面慢慢补。
- 目标：让一个没听过这想法的人，一句话就懂个大概。
- 追问示例：如果用户只说"一个冒险游戏"→ 追问"玩家具体操作什么？是打怪、解谜、经营，还是别的？"

### 第 2 项 · 核心循环 + 最想做好的那段
问：**"玩家会反复经历哪个过程？你希望他从中获得什么乐趣？"**
- 引导写成一条循环。例（刷装备地牢）：进入地牢 → 战斗获得装备 → 调整搭配变强 → 挑战新敌人 → 获得新装备。
- 然后必须追问那个关键问题：**"这条循环里，你最想做好的是哪一段体验？"**
  - 是战斗操作/策略带来的快感？
  - 是爆装备的爽感？
  - 还是调整搭配的思考乐趣？
- 强调：侧重点不同，游戏重点和系统投入就要相应调整。这一步决定了后面所有系统的优先级。

### 第 3 项 · 参考游戏（要具体到"参考什么"）
问：**"有哪些参考游戏？具体是参考它的什么？"**
- 关键：不能只写游戏名。要拆开——美术参考 A，战斗参考 B，装备设计参考 C。
- 向用户解释：这样写 AI 才更容易理解你的真实意图。
- 追问示例：用户说"参考《哈迪斯》"→ 追问"是参考它的战斗手感、美术风格，还是 roguelike 的解锁结构？"

### 第 4 项 · 资源、平台、时间限制
问：**"你手里有哪些现成资源？准备在什么平台运行？能投入多少时间？"**
- 这些限制会直接影响设计决策。
- 引导用户基于约束做取舍，并把取舍写进卡里。例：没有美术团队 → 用免费像素素材；想控制动作资源量 → 选回合制。
- 把"因为约束 X，所以决定 Y"这种因果显式写出来。

### 第 5 项 · 第一版范围 + 完成标准
问：**"第一版做到哪为止？怎么判断它算做完了？"**
- 核心概念：**最小闭环 / 核心循环**。第一版应让玩家能走完一次完整的最小闭环。
- 例（地牢）：先做一小段地牢，让玩家走完"探索 → 战斗 → 获得装备 → 用装备继续挑战"的完整闭环即算第一版完成。
- 明确告诉用户：大地图、大量职业、复杂系统 → 全部放到后面。第一版只保闭环。

### 收尾 · 找出没说清的地方
5 项填完后，不要直接结束。做机明强调的那一步：
1. 通读整张卡，**主动指出哪些地方还模糊、互相矛盾、或范围过大**。
2. 对每个模糊点给出 2-3 个具体选项，让用户选，而不是替他决定。
3. 和用户一起讨论，由**用户**决定哪些留下、哪些暂时不做。
4. 最后输出一张干净、完整的立项卡（用 references/kickoff-card-template.md 的结构）。

## 输出产物

- 一张填好的游戏立项卡（Markdown），结构见 `references/kickoff-card-template.md`。
- 可选：一段可直接复制给 AI 编程 Agent 的启动提示词，见 `references/ai-handoff-prompt.md`。
- 需要美术素材时，推荐 `references/art-resources.md` 里的免费资源站。

## 立项卡之后：用文档管理代码

当用户填完卡、准备真正开发时，提醒他机明的后续方法论（详见 `references/kickoff-card-template.md` 末尾）：
把游戏往下拆成一个个系统（战斗、装备、成长……），**每个系统对应一份系统策划案**。AI 必须根据系统策划案实现功能；有问题时用户只改文档、不直接改代码——**通过文档来管理整个游戏的代码**。立项卡是这套文档体系的第 0 份。

## 关键提醒（Pitfalls）

- ❌ 不要一次把 5 个问题全部抛出。逐项对话，拿到答案再追问。
- ❌ 不要替用户做创意决定。给选项，让他拍板。
- ❌ 不要让用户在第 2 项只写循环不选"最想做好的一段"——这是最常被跳过、却最关键的一步。
- ❌ 参考游戏只写名字 = 没说清。一定追问"参考它的什么"。
- ✅ 第一版范围一定要收敛到一个可完成的最小闭环，别让它膨胀。
- ✅ 全程用用户自己的语言复述他的想法，让他感到"思路越填越清楚"。
